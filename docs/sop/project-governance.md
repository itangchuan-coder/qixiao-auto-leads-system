# 项目长期开发规范 SOP

## 使用场景

当系统准备持续迭代，不再只是随便试一试，而是要长期增加模块、字段和流程时使用。

## 目标

让这个项目在后续增加供应商、客户项目、成交开拓基地、报价、权限和真实接口时，结构不容易乱，开发步骤可重复。

## 开发原则

1. 先做业务闭环，再做高级能力。
2. 第一版优先前端原型，后续再逐步接真实后端。
3. 新增模块时，先统一字段，再写页面。
4. 每增加一个核心业务模块，同步更新 SOP。
5. 优先沿用现有 Ant Design 组件和当前项目结构，不轻易大改架构。

## 推荐目录职责

- `src/App.tsx`：页面主入口、路由和整体布局。
- `src/domain/types.ts`：所有业务类型定义。
- `src/domain/mockData.ts`：模块的模拟数据。
- `src/domain/helpers.ts`：编号、标签、格式化等公共方法。
- `src/domain/referenceData.ts`：城市、品牌、车型这类选择基础数据。
- `src/components/`：可复用组件，例如智能选择器。
- `docs/sop/`：业务流程和使用手册。

## 新增业务模块的标准步骤

1. 先写清楚模块名称、给谁用、解决什么问题。
2. 列清楚字段。
3. 明确筛选条件、列表列、详情信息、表单项。
4. 明确谁能看、谁能改、谁能操作。
5. 先补类型定义。
6. 再补 mock 数据。
7. 再开发列表、详情、表单。
8. 加入菜单入口。
9. 手动验证流程是否能跑通。
10. 更新对应 SOP。

## 字段设计规则

- 同一个业务概念，字段命名保持一致。
- 状态字段尽量使用统一枚举，不要每个页面各写一套。
- 城市、品牌、车型优先使用现有智能选择方式。
- 可选项很多时，要支持搜索。
- 后续可能接后端的字段，不要只为了页面展示临时乱命名。

## 页面设计规则

- 后台系统页面以“筛选区 + 表格区 + 详情/弹窗操作”为主。
- 表格优先展示核心信息，不要一次塞太多列。
- 操作按钮只放核心动作，次要内容放详情。
- 表单按业务顺序排列，不按想到什么写什么。

## 角色与权限规则

- 管理员默认完整权限。
- 运营优先拥有核心流程操作权限。
- 其他角色先预留结构，后面再细分。
- 做页面时至少考虑：谁能看、谁能新增、谁能编辑、谁能导出。

## 发布规则

每次准备交付前至少执行：

```bash
pnpm build
pnpm lint
```

然后人工检查关键页面和流程。

## Git 规则

- 每做完一小块就提交一次，不要攒太久。
- 提交说明尽量说人话，能看出改了什么。
- 功能开发完成后及时推到 GitHub。

示例：

```bash
git add .
git commit -m "feat: add supplier management module"
git push
```

## 常见问题

- 模块越做越乱：通常是没有先梳理字段和流程。
- 页面字段对不上：通常是类型、mock 数据、表格列没同步。
- SOP 过期：每次改业务后要顺手更新。

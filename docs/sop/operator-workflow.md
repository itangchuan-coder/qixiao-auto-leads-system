# 运营岗位工作 SOP

## 适用范围与职责

适用于负责线索处理、项目执行、供应商维护和成交产能跟进的运营人员。当前原型中，运营与管理员拥有相同的录入、编辑和状态流转权限；涉及预算批准、对外付款和最终结算时，运营仅负责提交事实与留痕，由主管在线下确认。

## 通用要求

- 以系统记录为唯一业务台账；每次状态变化、异常和人工判断必须写入备注或跟进记录。
- 不得将重复、待清洗、无效或已交付线索再次交付。
- 不得以“首付款已到账”“成本公司承担”“成交成功”等字段替代财务凭证或主管批准。
- 当前版本是浏览器内 mock 数据，刷新页面会恢复初始样例；当日需要留存的结果，应在刷新前按公司规定导出或另存。

## 场景一：线索录入、清洗与交付

### 操作目的

将来自渠道、表单或人工收集的购车意向统一入库，识别重复和无效数据，再将可交付线索按正确对象和批次下发。

### 操作方式

1. 单条录入：进入「线索管理」，点击「新增线索」，填写姓名、手机号、城市、意向品牌/车型、预算、购车时间、来源、负责人和备注后保存。
2. 批量录入：进入「线索导入」，上传文件执行模拟导入。当前原型会新增 1 条待清洗和 1 条重复示例，不能解析实际 Excel；正式批量导入须另行使用统一模板和人工登记。
3. 清洗：在线索管理中打开详情，按照「新线索 -> 待清洗 -> 有效/重复/无效」流转。核对手机号、城市、意向、来源和联系结果；把判断依据写入跟进记录。
4. 去重：同手机号保留信息更完整、时间更近且可联系的一条；另一条标记为「重复」或「无效」，备注保留原始来源和合并原因。
5. 交付：先在「交付对象」确认对象处于启用状态；在「线索管理」仅勾选「有效」线索，进入「交付批次」选择交付对象并写清筛选条件、数量和对账口径，创建批次。
6. 交付后核对：确认所选线索变为「已交付」，详情中新增批次编号和交付对象的自动跟进记录。

### 完成标准

- 每条新线索都有来源、负责人和处理状态。
- 有效线索有清洗依据；批次内全部线索均为有效状态。
- 已交付线索不再被重复交付，批次备注可用于后续对账。

## 场景二：项目建立与执行交接

### 操作目的

把销售确认的下游需求、交付规则、负责人和结算基础建立为可追踪项目，避免口头需求直接进入交付。

### 操作方式

1. 进入「客户项目管理」，点击「新增项目」。
2. 填写客户名称、项目类型、供给对象、主机厂/品牌、销售负责人、运营负责人、供给内容、需求量级和推送时间。
3. 完整登记业务规则：首触、有效率、系统排重、精准下发、成交/到店凭证、单店限制和其他要求。
4. 完整登记合同与结算基础：合同编号、首付款金额及到账状态、结算方式、账期、发票形式、单价、结算标准、耗损比例和备注。
5. 新项目保持「待启动」，由主管完成准入复核后再流转「执行中」。执行异常时流转「暂停」并在备注写清原因；执行完成后流转「已完成」，对账确认后由主管确认进入「已结算」。
6. 在「个人业务驾驶舱」按负责人查看项目、待报价和风险；发现首付款未到账、长账期或凭证要求时，按当日优先级上报主管。

### 完成标准

- 项目有明确的客户、量级、负责人、交付规则和结算口径。
- 未经准入复核的项目不进入「执行中」。
- 项目状态与实际执行、合同和对账进度一致。

## 场景三：供应商建档与合作维护

### 操作目的

维护渠道方、数据方的基础档案和合作条件，确保采购或接入前能判断合同、付款模式和合作状态。

### 操作方式

1. 进入「供应商管理」，点击「新增供应商」。
2. 填写供应商名称、类型、联系人、联系电话、合同起止日期、付款模式、账期、合作状态和备注。
3. 在备注中写明供给范围、结算口径、质量基线、历史问题及暂停原因；合同或结算附件当前只能记录编号或外部存放位置。
4. 每周筛选并复核合同 30 天内到期的供应商；续约未完成或质量异常时改为「暂停」，终止合作时改为「已终止」并记录生效日期和原因。
5. 供应商恢复合作前，取得主管确认并更新合同、质量要求和付款条件。

### 完成标准

- 合作中供应商均有有效合同日期、付款模式和账期。
- 暂停/终止状态与实际采购状态一致，原因可追溯。
- 运营不在系统中虚构付款完成或合同审批结论。

## 场景四：费用支配与成交产能跟进

### 操作目的

在现有功能边界内，记录成交资源的预算事实、付款条件、垫付风险和成交结果，为主管的费用批准和财务核销提供依据。

### 操作方式

1. 进入「成交开拓基地」，新增产能并填写城市、品牌、门店、联系人、供应内容、凭证编号、供应时间、产能、付款模式、金额、对接人和付款人。
2. 初始状态使用「待联系」，按真实进展依次流转「已建立联系 -> 可供应 -> 已预占 -> 已交割 -> 成交成功/成交失败」。
3. 预付项在「已预占」前，运营必须向主管提交：项目/需求关联、金额、付款方式、供应凭证、预期产能、风险和失败承担建议；获批后才可在线下执行付款。
4. 付款执行后，仅在字段和备注中记录付款人、付款时间、凭证编号和付款结果，不将系统中的金额字段视为付款指令或审批单。
5. 成交失败时填写失败原因；是否由公司承担成本只能在主管/财务确认后勾选。预付且未成功事项每日在个人驾驶舱复核并上报。

### 完成标准

- 每笔费用相关事项都有业务目的、金额、付款模式、责任人和凭证索引。
- 预付事项可从产能记录追溯到主管批准和财务凭证（审批与凭证暂存于系统外）。
- 成功/失败结论与成本承担结论同步更新，不留长期未知状态。

## 升级与异常处理

- 发现重复率异常、客户投诉、合同到期、首付款未到账、预付未成交或交付口径不一致时，当日记录并通知主管。
- 无法确认的状态不要强行推进；保持当前状态，补充事实后请求主管决策。
- 手机号和联系人仅用于业务处理，不得向无授权对象导出或展示。
